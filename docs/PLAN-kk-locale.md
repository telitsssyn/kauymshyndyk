# План: казахская версия интерфейса сайта (`/kk`)

Документ — задание для исполнителя. Читать целиком до начала работы.

## Цель

У сайта появляется вторая локаль `kk`. На казахский переводится **интерфейс**: меню, кнопки,
заголовки разделов, подписи, подвал, страница-таплинк, даты. Всё остальное остаётся русским.

Готово, когда:

- `/kk` и все разделы открываются, интерфейс на казахском, казахские буквы (Қ Ғ Ү Ұ Ә Ө Ң І Һ)
  отрисованы тем же шрифтом, что и остальные;
- в шапке и в таплинке есть переключатель языка, который ведёт на ту же страницу в другой локали;
- русская версия не изменилась ни внешне, ни по адресам;
- `npx tsc --noEmit`, `npm run lint`, unit-тесты и `npm run build` проходят.

## Решения, которые уже приняты (не пересматривать)

| Вопрос | Решение |
| --- | --- |
| Контент из админки (новости, проповеди, расписание, тексты страниц, название церкви) | Не переводится. В `/kk` показывается тот же русский контент. |
| Библия | Открывается внутри `/kk` (шапка, меню и подвал казахские), но сам раздел — текст, кнопки читалки, толкования — остаётся русским. |
| Адреса страниц | Те же слаги, что в русской версии: `/kk/raspisanie`, `/kk/novosti/...`. Отличается только префикс. |
| «Политика конфиденциальности» и «Условия использования» | Переводится только заголовок. Текст остаётся русским, над ним — короткая пометка на казахском. |

## Чего не трогать

- `src/payload.config.ts` (блок `localization`), коллекции, глобалы, `src/migrations/` —
  локаль `kk` в Payload **не добавляется**, миграции не нужны.
- `public/bible/`, `src/data/bible/`, компоненты `src/components/bible/` (кроме обёртки с `lang`, см. шаг 6).
- `src/lib/revalidate.ts` — пути там содержат `[locale]` и новую локаль покрывают сами.
- `src/lib/queries.ts` — запросы не передают локаль и поэтому всегда отдают русский контент. Так и надо.

## Особенности окружения

- Сборка только через `npm run build` (внутри `next build --webpack`). Turbopack ломает админку.
- Unit-тесты запускать через PowerShell из пути с заглавной буквой диска:
  `Set-Location C:\Projects\kauymshyndyk; npm run test:unit`. Из Git Bash (`/c/...`) они падают
  с «No test suite found» — это не поломка тестов.
- `python` недоступен, для скриптов — `node`.
- Проверка вживую описана в скилле `verify` (`.claude/skills/verify/SKILL.md`).
- Тяжёлые процессы (сборка, dev-сервер, headless-браузер) запускать по одному и останавливать после проверки.
- В рабочей папке могут лежать незакоммиченные изменения владельца — не откатывать и не «чинить» их.
- Коммиты — только по прямой просьбе владельца, без упоминаний ИИ и без `Co-Authored-By`.

## Шаг 1. Маршруты

Файл `src/i18n/routing.ts`.

- `locales: ['ru', 'kk']`, `defaultLocale` остаётся `'ru'`.
- Слаги одинаковые для обеих локалей, поэтому значения в `pathnames` заменить с объектов на строки:
  `'/schedule': '/raspisanie'` вместо `'/schedule': { ru: '/raspisanie' }`.
- Экспортировать тип локали (`export type Locale = (typeof routing.locales)[number]`).
- Обновить комментарий в начале файла.

`src/middleware.ts` не менять. Определение языка по браузеру оставить включённым: посетитель с
казахским языком браузера попадёт с `/` на `/kk`, остальные — на `/ru`, как сейчас.

## Шаг 2. Шрифты

Файл `src/app/(frontend)/[locale]/layout.tsx`. У `Inter` и `Oswald` сейчас
`subsets: ['latin', 'cyrillic']`. Специфические казахские буквы лежат в наборе `cyrillic-ext` —
добавить его обоим шрифтам. Без этого Қ, Ғ, Ү, Ұ, Ә, Ө, Ң будут подставляться из запасного шрифта.

## Шаг 3. Локаль в `generateMetadata` — обязательная правка

Сейчас `generateMetadata` на страницах и `buildMetadata` в `src/lib/metadata.ts` узнают язык через
`getLocale()` / `getTranslations('ns')` без явной локали. С одной локалью это работало, потому что
запасной вариант — `ru`. С двумя локалями так нельзя: `setRequestLocale` вызывается в теле
страницы, а `generateMetadata` может выполниться раньше, и казахская страница получит русские
`<title>` и канонический адрес. Правило next-intl: в `generateMetadata` локаль берут из `params`.

Сделать:

1. `buildMetadata` получает обязательный параметр `locale` и больше не вызывает `getLocale()`;
   переводы берёт через `getTranslations({ locale, namespace: 'meta' })`.
2. В каждом `generateMetadata` (все `page.tsx` в `src/app/(frontend)/[locale]/**` и `layout.tsx`
   локали) достать `locale` из `params` и передать явно и в `getTranslations({ locale, namespace })`,
   и в `buildMetadata`.
3. В `buildMetadata` добавить `alternates.languages` — адреса этой же страницы в `ru` и `kk`
   (через `getPathname`) плюс `x-default` на русскую.
4. Для страниц с русским содержимым (Библия, политика, условия) в `/kk` канонический адрес должен
   указывать на **русскую** версию, а `languages` не выставляется. Удобно сделать опцией
   `buildMetadata`, например `contentLocale: 'ru'`.

## Шаг 4. Словарь `kk.json`

Создать `src/i18n/messages/kk.json` с точно той же структурой ключей, что у `ru.json`.

- Перевести все пространства имён, **кроме `bible`**: его скопировать из `ru.json` без изменений.
- `nav.bible` и `nav.bibleDesc` перевести — это пункты меню, а не раздел.
- ICU-плейсхолдеры (`{churchName}`, `{date}`, `{page}`, `{total}`, `{caption}`, `{book}` и т.п.)
  сохранять буква в букву.
- В `legal` добавить в оба файла ключ `russianOnly` (в `kk` — «Құжат мәтіні орыс тілінде берілген»,
  в `ru` — «Текст документа приведён на русском языке»).
- Название церкви не переводить — оно приходит из админки.

Ориентир по терминам (проверит носитель, см. шаг 10):

| Русский | Казахский |
| --- | --- |
| церковь (община) | қауым |
| богослужение | ғибадат |
| проповедь | уағыз |
| Библия | Киелі кітап |
| служители | қызметшілер |
| пожертвование / пожертвовать | садақа / садақа беру |
| расписание | кесте |
| новости / события | жаңалықтар / іс-шаралар |
| контакты | байланыс |
| Я здесь впервые | Мен мұнда алғаш рет келдім |

Тон — как в русском тексте: тёплый, простой, без канцелярита. Обращение на «сіз».

## Шаг 5. Строки, зашитые в код

Найдено проверкой по кириллице вне комментариев:

- `src/components/ReelsSection.tsx` — 18 строк: `aria-label` кнопок, «Видео #N», «N из M»,
  пункты меню плеера. Вынести в словарь (новое пространство `reels` в обоих файлах) и брать через
  `useTranslations('reels')`.
- `src/app/(frontend)/[locale]/(site)/privacy/page.tsx` и `terms/page.tsx` — текст **остаётся
  русским**. Нужно: показать над текстом пометку `legal.russianOnly`, только когда `locale !== 'ru'`,
  и поставить `lang="ru"` на контейнер с текстом.
- `src/app/(frontend)/[locale]/(site)/page.tsx` — `addressLocality: 'Павлодар'` в JSON-LD оставить.
- `src/lib/schedule.ts`, `formatTime` с локалью `'ru'` — оставить, это формат «ЧЧ:ММ».

Даты переводить не нужно: `getFormatter()` и `formatDateLabel` уже работают от текущей локали,
Node знает казахский («10 қараша, сейсенбі»).

## Шаг 6. Библия в `/kk`

- `bible/[book]/[chapter]/page.tsx`: `generateStaticParams` получает параметры родителя —
  возвращать список глав только для `ru`, для остальных локалей пустой массив. Казахские адреса
  соберутся при первом заходе и останутся в кэше (`revalidate = false` уже стоит). Сборка не удлиняется.
- На обеих страницах раздела обернуть содержимое (хлебные крошки можно оставить снаружи) в элемент
  с `lang="ru"`, когда локаль не русская.
- Метаданные — по шагу 3, пункт 4.

**Обязательная проверка после сборки** (см. шаг 9): `/kk/bibliya/john/3` отвечает 200, второй
запрос — из кэша. В проекте уже был случай, когда страницы, не собранные заранее, на проде падали
с `DYNAMIC_SERVER_USAGE`. Если это повторится — сначала убедиться, что в цепочке рендера страницы
нет вызовов next-intl без явной локали до `setRequestLocale`; если не поможет, собрать главы
заранее и для `kk`.

## Шаг 7. Переключатель языка

Новый клиентский компонент `src/components/LanguageSwitcher.tsx`.

- Две ссылки: «РУС» и «ҚАЗ». Текущая выделена и помечена `aria-current="true"`; у каждой
  `lang` и `hrefLang`; у группы `aria-label` из словаря (`common.language`).
- Ведёт на **ту же** страницу в другой локали: `usePathname()` из `@/i18n/navigation` и
  `useParams()` из `next/navigation`, ссылка — `<Link href={{ pathname, params }} locale="kk">`
  (типизация тут строгая; допустим один `@ts-expect-error` с пояснением, как в документации next-intl).
- Строку запроса (`?page=2`) сохранять.

Где разместить:

- `src/components/Header.tsx` — в блоке «Действия справа», перед кнопкой «Пожертвовать»; на узких
  экранах скрыть там и показать внизу мобильного меню.
- `src/app/(frontend)/[locale]/links/page.tsx` — таплинк без шапки, поэтому маленький переключатель
  вверху страницы.

Стиль — существующие классы и цвета шапки, без новых зависимостей.

## Шаг 9. Проверка

По порядку, тяжёлые процессы по одному:

1. `npx tsc --noEmit`, `npm run lint`, unit-тесты (через PowerShell).
2. `npm run dev:db`, затем `npm run build`. В отчёте сборки: у `/[locale]/bible/[book]/[chapter]`
   по-прежнему ~1189 путей (не 2378); казахские версии обычных страниц собраны.
3. `npm start` и проверить запросами:
   - `/` с `Accept-Language: kk` → редирект на `/kk`; без заголовка → `/ru`;
   - у `/kk/raspisanie`: `<html lang="kk">`, казахский `<title>`, канонический адрес `/kk/raspisanie`,
     `hreflang` на обе версии;
   - у `/kk/bibliya/john/3`: 200, канонический адрес ведёт на `/ru/bibliya/john/3`, второй запрос
     с `x-nextjs-cache: HIT`;
   - `/ru/raspisanie` — заголовок и канонический адрес прежние;
   - `/sitemap.xml` содержит `/kk/novosti`, не содержит `/kk/bibliya`.
4. Скриншоты (`npx playwright screenshot`) главной `/kk` на ширине 1280 и 375: переключатель на
   месте, длинные казахские подписи не ломают шапку и кнопки, казахские буквы в заголовках тем же
   шрифтом, что соседние.
5. Остановить сервер и базу.
